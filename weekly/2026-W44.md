This week featured 3 updates from Microsoft Devblogs.

This week’s updates cover enhancements to developer productivity tools, including a new PostgreSQL extension for VS Code and a secure publishing method for Visual Studio Marketplace extensions. A technical experiment on workspace path naming is also discussed, with findings indicating minimal impact on agent behavior.

Detailed list:

* [PostgreSQL Like A Pro: Build, query, and troubleshoot without leaving VS Code](https://devblogs.microsoft.com/blog/postgresql-like-a-pro-vscode/). - The PostgreSQL extension for VS Code enables developers to perform common database tasks—such as connecting to a database, writing and reviewing SQL queries, exploring database objects, and investigating performance issues—directly within the VS Code environment. It supports connections to on-premises and cloud databases, including Azure PostgreSQL with Microsoft Entra ID, and integrates with GitHub Copilot for assistance. The extension provides tools for browsing schemas, writing SQL with IntelliSense, analyzing query performance, and tracing database relationships, all within the editor.
* [Publish Visual Studio Marketplace extensions securely with Trusted Publishing](https://devblogs.microsoft.com/blog/trusted-publishing-visual-studio-marketplace/). - Microsoft announced Trusted Publishing for Visual Studio Marketplace, a method to publish Visual Studio Code and Visual Studio extensions from GitHub Actions or Azure Pipelines without storing a long-lived Azure DevOps personal access token. The service uses federated identity to verify the CI/CD workflow and grant access, eliminating the need for a publishing secret. It supports both GitHub Actions (via OIDC) and Azure Pipelines (via Workload Identity Federation). Existing PAT-based publishing continues to function.
* [Does ‘eval’ in the workspace path change what your agent does?](https://devblogs.microsoft.com/blog/does-eval-in-the-workspace-path-change-what-your-agent-does/). - The announcement describes an experiment testing whether the folder name "eval" in a workspace path affects agent behavior. It confirms that the folder name is visible to the model in the system prompt and increases the agent's suspicion of being tested, but does not meaningfully change the agent's actions across multiple models and scenarios. The practical significance is that folder names describing evaluation (e.g., "eval") may influence agent confidence but not task execution, while names describing work (e.g., "poc") may subtly affect behavior. The study used 900 runs across four models to measure behavior changes, finding no significant difference in output, effort, or honesty.
