This week featured 13 updates from Microsoft Azure Updates.

This week’s Azure updates highlight ongoing advancements in cloud infrastructure, including preview features for file synchronization, edge computing, and performance monitoring, alongside the retirement of support for certain .NET versions and Azure Data Share. A recurring theme is the introduction of new capabilities in Azure Front Door, Azure Functions, and Azure SQL Managed Instance, while maintaining backward compatibility for existing services. Notable exceptions include the retirement of .NET 8 and .NET 9 support for Static Web Apps and the upcoming retirement of Azure Data Share in 2029.

Detailed list:

* [\[In preview\] Public Preview: Modernize Arc-enabled Windows Servers with Azure File Sync](https://azure.microsoft.com/updates?id=579854). - Azure File Sync offers a preview experience that guides users through deploying Arc-enabled Windows Servers to Azure Files, allowing hybrid access or migration while maintaining local file server functionality. The service enables centralized file storage in Azure, optimized local storage via cloud tiering, and simplifies deployment through a single Azure portal workflow.
* [Retirement: Support for .NET 8 and .NET 9 on Static Web Apps is ending November 10, 2026](https://azure.microsoft.com/updates?id=575106). - Azure Static Web Apps will stop supporting .NET 8 and .NET 9 for managed Functions APIs on November 10, 2026. Applications will continue to operate but will no longer receive security updates or vendor support. To remain on a supported version, APIs must be upgraded to .NET 10. The announcement provides steps for migrating from the in-process model to the isolated worker model or updating the isolated worker model to target .NET 10.0. The API project's TargetFramework and staticwebapp.config.json platform.apiRuntime must both reference .NET 10.0. After completing the required upgrades, the API must be redeployed so Azure Static Web Apps publishes it on .NET 10. A separate deployment process applies to linked Function Apps.
* [Public Preview: Azure Route Server dual-stack IPv4/IPv6 support](https://azure.microsoft.com/updates?id=579746). - Azure Route Server now supports dual-stack IPv4/IPv6 mode in public preview, allowing route exchange for both address families across supported hybrid networking connections. Existing IPv4 connections remain unchanged.
* [\[Launched\] Generally Available: Azure Front Door edge actions](https://azure.microsoft.com/updates?id=579310). - Azure Front Door edge actions are now generally available. These serverless compute functions allow customers to execute lightweight JavaScript during client request/response processing at the edge. The service supports scenarios such as A/B testing, canary deployments, header manipulation, request filtering, dynamic origin selection, advanced routing, authentication/authorization at the edge, and other use cases. Edge actions integrate with Azure Front Door features including rules engine, caching, routing, and Web Application Firewall (WAF). They are built on Hyperlight, Microsoft’s secure micro-VM technology, providing hardware-backed isolation for customer code execution.
* [\[In preview\] Public Preview: Azure Front Door adds native gRPC support](https://azure.microsoft.com/updates?id=579383). - Azure Front Door Standard and Premium are in public preview with native gRPC support. This allows routing gRPC calls to specific services and methods, distributing traffic across healthy origins, and using Azure Front Door security and routing capabilities. gRPC operates over HTTP/2 and HTTPS from client to origin, supporting unary and streaming RPCs. gRPC health probes can be used for load balancing to healthy origins.
* [\[Launched\] Generally Available: Azure Functions support for .NET 11](https://azure.microsoft.com/updates?id=578773). - Azure Functions support for .NET 11 is now generally available. Developers can build Azure Functions apps targeting .NET 11 using the isolated worker model, while continuing to use the Azure Functions programming model and host integration. The release includes runtime performance optimizations, richer APIs, and enhanced developer tooling via the latest .NET runtime, C#, library, and SDK improvements.
* [\[In preview\] Public Preview: Distributed accelerator for cloud storage on AKS](https://azure.microsoft.com/updates?id=578454). - Azure has announced a public preview of DACS, a distributed read-through cache for AI workloads running on Azure Kubernetes Service (AKS). DACS uses local NVMe disks within the AKS cluster to cache frequently read data from Azure Blob Storage, reducing repeated reads and improving performance for inference and training workloads. The cache is managed through Azure Container Storage and can be integrated using Run:ai Model Streamer, BlobFuse2, or the native Python client. Azure Blob Storage remains the primary data source, and clients read directly from it when the cache is not in use or unavailable.
* [\[In preview\] Public Preview: Rate limit grouping for Azure Front Door Premium WAF](https://azure.microsoft.com/updates?id=580155). - Azure Front Door Premium WAF is introducing a public preview feature called rate limit grouping. This feature allows rate limit rules to count requests based on shared client attributes—such as JA4 fingerprint, AS number, country/region, or all requests—rather than only per client IP address. The feature helps mitigate distributed attacks by aggregating traffic from multiple IPs into a single threshold. Users can configure grouping through the Azure portal, ARM templates, Bicep, REST API, or Azure PowerShell. Existing per-IP rate limit rules remain unchanged unless a grouping is selected.
* [\[In preview\] Public Preview: SQL performance monitoring for Azure SQL Managed Instance](https://azure.microsoft.com/updates?id=574158). - Microsoft has announced a public preview of performance monitoring for Azure SQL Managed Instance. The service collects and stores performance telemetry and provides dashboards at the resource level and at scale to help identify performance trends, anomalies, and bottlenecks. It also allows secure querying of monitoring data using Kusto Query Language (KQL) through an RBAC-protected Azure Data Explorer proxy endpoint.
* [\[In preview\] Public Preview: Auto scaling of ingestion limits in Azure Monitor workspace](https://azure.microsoft.com/updates?id=578207). - Azure Monitor Workspace (AMW) now includes a preview feature that automatically scales ingestion limits based on usage patterns. This feature adjusts the ingestion quota ceiling up or down depending on observed usage, helping to maintain healthy utilization. The capability is available in preview and is intended for use within Azure Monitor Workspace.
* [\[Launched\] Generally Available: Azure Front Door mutual TLS authentication](https://azure.microsoft.com/updates?id=577678). - Azure Front Door Premium now supports mutual TLS (mTLS) authentication using X.509 client certificates. This feature is available for business-to-business, Internet of Things, financial services, and enterprise scenarios. Four authentication modes are offered: require and validate, require without validation, validate when presented, and pass through to the origin. Client certificates are sent via the X-Azure-ClientCertificate header. Trusted CA configuration is simplified by uploading only the root CA certificate to Azure Key Vault and associating it with a custom domain. When edge validation is enabled, Azure Front Door validates the certificate chain at request time.
* [\[In preview\] Public Preview: JWT validation with Azure Front Door Auth Policy](https://azure.microsoft.com/updates?id=577673). - Azure Front Door Premium now offers a public preview of JWT validation through its Auth Policy. This feature allows validation of bearer tokens issued by Microsoft Entra ID at the edge, enabling centralized authentication checks. The preview supports associating the Auth Policy with a profile, domain, or route, and configuring the expected issuer and audience. It operates in Block mode to reject invalid or missing tokens with HTTP 401 responses or in Log mode to evaluate such requests. The preview validates existing tokens only; application-specific authorization remains the responsibility of the user. Origin access must be restricted to prevent bypassing Azure Front Door.
* [Retirement: Azure Data Share will be retired on November 12, 2029](https://azure.microsoft.com/updates?id=578818). - Azure Data Share will be retired on November 12, 2029. The service is intended for data providers, recipients, and applications that currently use Azure Data Share for snapshot-based or in-place sharing. Transitioning to Microsoft Fabric is recommended, with options including Fabric external data sharing, Azure Data Factory or Fabric Data Factory pipelines, Azure SQL Database data virtualization (preview), or file queries. Inventory and validate all related resources and dependencies before making changes. Use existing Azure support channels until the retirement date.
