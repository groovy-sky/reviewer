This week featured 6 updates from Microsoft Azure Updates.

The digest covers a mix of preview and general availability updates, including centralized JWT validation for Application Gateway for Containers, crash-consistent restore points for Premium SSD v2 and Ultra Disks, IPv6 application rules for Azure Firewall, general availability of Route maps for Azure Route Server, PostgreSQL REST API enhancements, and TLS key exchange policies with post-quantum support for Azure Front Door.

Detailed list:

* [\[In preview\] Public Preview: JWT validation for Application Gateway for Containers](https://azure.microsoft.com/updates?id=576382). Application Gateway for Containers now supports centralized JSON Web Token validation through the AuthPolicy custom resource. It validates token signature, issuer, lifetime, and audience using signing keys from a trusted HTTPS JSON Web Key Set endpoint. Requests with missing or invalid credentials are rejected at the gateway. AuthPolicy can protect ApplicationLoadBalancer, Gateway, HTTPRoute, GRPCRoute, or MCPRoute. Policies inherit through the resource hierarchy, with route-level policies able to replace or opt out of inherited policies. Optional OAuth Protected Resource Metadata enables authorization server discovery. Apply consistent JWT validation to HTTP, gRPC, and MCP routes. Use Microsoft Entra ID or third-party identity providers that publish trusted JWKS signing keys. Combine JWT validation with WAF for malicious traffic inspection. Publish OAuth resource metadata to enable authorization server discovery.
* [\[In preview\] Public Preview: Multi-disk crash-consistent VM restore points for Premium SSD v2 and Ultra Disks on VMs with SCSI disk controller](https://azure.microsoft.com/updates?id=579162). Multi-disk crash-consistent restore points are now available in public preview for Azure VMs with Premium SSD v2 and Ultra data disks using SCSI disk controllers. Instant Access is supported, allowing immediate disk restoration. This preview extends existing support to Premium SSD v2 and Ultra data disks only; Standard HDD, Standard SSD, and Premium SSD disks remain unchanged. The change applies only to VMs with Premium SSD v2 and Ultra data disks.
* [\[In preview\] Public Preview: Azure Firewall IPv6 now supports application rules](https://azure.microsoft.com/updates?id=579507). Azure Firewall now supports application rules in IPv6 Public Preview, enabling layer 7 filtering for IPv6 HTTP and HTTPS traffic. The enhancement extends application-level controls to IPv6 and dual-stack deployments. This preview is limited to IPv6 HTTP and HTTPS traffic, dual-stack deployments, and is available in preview only.
* [Generally Available: Route maps for Azure Route Server](https://azure.microsoft.com/updates?id=578966). Route maps for Azure Route Server are now generally available in the Azure public cloud. They provide fine-grained control over inbound and outbound routing across hybrid connections, including ExpressRoute, VPN, and Network Virtual Appliances. Route maps enable route summarization, route control, path selection, and route tagging.
* [\[Launched\] Generally Available: Azure Database for PostgreSQL stable REST API version 2026-10-01](https://azure.microsoft.com/updates?id=579300). The Azure Database for PostgreSQL Flexible Server REST API version 2026-10-01 is now generally available, introducing expanded capabilities for maintenance management, immutable backups, multi-tenant encryption with customer-managed keys, FIPS configuration, network migration, Premium SSD v2 storage, and major version upgrade prechecks, while enhancing autonomous tuning recommendations and PostgreSQL version handling.
* [\[Launched\] Generally Available: Azure Front Door TLS key exchange policy with post-quantum support](https://azure.microsoft.com/updates?id=577668). Azure Front Door now supports configurable TLS key exchange policies, including hybrid post-quantum key exchange, to prepare for evolving cryptographic threats while meeting security and client compatibility requirements. Choose a predefined Standard or Enhanced policy or use a Custom policy to select supported classical and hybrid post-quantum key exchange groups, including X25519. Hybrid post-quantum key exchange requires TLS 1.3 and protects client-to-edge connections; it does not apply to connections from Azure Front Door to your origin. For additional control over TLS encryption, Azure Front Door also supports disabling the TLS\_AES\_128\_GCM\_SHA256 cipher suite when TLS 1.3 is configured as the minimum TLS version in TLS Policy.
